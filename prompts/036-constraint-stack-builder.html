036 Prompt Engineering Intermediate

Constraint Stack Builder

Use this to organise multiple prompt constraints without creating contradictions.

Use case: A communications, teaching, or operations team can create reliable instructions involving length, tone, content, and compliance limits.

Best tools

  • ChatGPT — Organises detailed constraints and detects conflicts through interactive refinement.
  • Gemini — Handles structured instruction design and offers alternative constraint resolutions.

Act as a constraint engineer for the task [TASK], turning my requirements into a coherent prompt. Raw requirements: [REQUIREMENTS]. Intended audience: [AUDIENCE]. Required output: [OUTPUT]. First sort every requirement into four layers: safety and truthfulness, task essentials, format limits, and style preferences. Assign each item Hard, Strong Preference, or Optional. Search for collisions such as “comprehensive but 100 words,” “friendly but legally exact,” incompatible formats, or missing data required by a hard rule. For each collision, show the competing instructions and offer two resolutions. Ask me to decide whenever the choice changes the goal; do not silently pick. Build the final prompt with the constraints placed near the action they govern. Add a precedence rule stating what wins if requirements conflict. Translate fuzzy terms—professional, concise, engaging, detailed—into observable boundaries using [EXAMPLES_OR_METRICS]. Include a compact compliance checklist the model can complete after drafting. It should report pass, fail, or not applicable, then revise once only for failed hard constraints. Ensure the check does not invite fabricated facts merely to satisfy format. Return: the sorted stack, unresolved choices, final prompt, and one edge-case test. End by identifying the first constraint to relax if the requested output proves impossible, with a reason tied to the stated priorities.
